# ERRC Review — cargo-cicd as Fleet Front Door

## Eliminate

- **Delete or wire the `anti-llm-cheat` feature's dead `LspNoun`** — `src/legacy_nouns/lsp.rs`, `Cargo.toml` — Every other `legacy_nouns` submodule (evidence, git, sbom, pipeline, publish, target, test, trybuild, workspace, certification) has a matching `src/nouns/*.rs` wrapper that registers it with the dispatcher; `lsp` does not. Building with `--features anti-llm-cheat` compiles a command surface that is unreachable from the CLI. Severity: medium.
- **Prove or retract the "kept on stable" claim for `wasm4pm-compat`** — `Cargo.toml`, `rust-toolchain.toml`, `.github/workflows/ci.yml` — `rust-toolchain.toml` pins the whole workspace to `nightly-2026-06-22` and every CI job uses `dtolnay/rust-toolchain@nightly`; no job ever builds on stable. The comment claiming the `affidavit` feature is kept out-of-process "to keep this build on stable" is currently untested and likely false. Add a real stable CI job or delete the claim. Severity: medium.
- **Remove the duplicate first/second-generation adapter pairs** — `src/adapters/mod.rs` (`cargo_meta` vs `cargo_metadata`, `git` vs `git_status`, `target` vs `target_scanner`, `trybuild` vs `trybuild_detector`, `changed_files` vs `changed_file_detector`) — `EngineState::from_workspace()` only calls the second-generation adapters; the first-generation modules (~450 lines) are unreferenced outside their own files. Delete the unused twins and fold any still-needed re-export into the survivor. Severity: low.
- **Add a lint that locks in the current "no `unsafe`, no shell string interpolation" discipline** — repo-wide (`src/**/*.rs`) — A full grep today finds zero `unsafe` blocks and every `Command::new` call uses discrete `.arg()`/`.args()` with no `sh -c`/`bash -c`. This is true only by convention; nothing stops a future ggen-scaffolded noun from regressing it. Generalize the partial detection already in `src/nouns/doctor.rs` into a real CI check. Severity: low.
- **Split `docs/` into newcomer vs. vision/compliance tiers** — `docs/` top level (`ROADMAP-2030.md`, `VISION-2030-INDEX.md`, `thesis.md`, `IEC-61508-MAPPING.md`, `ISO-26262-MAPPING.md`, `SOC2-MAPPING.md`, `TOGAF-ADM-COVERAGE.md`, `CARGO-EVIDENCE-RFC.md`, `distributed-oracle-design.md`, `CERT-BODY-INTEGRATION.md`, etc.) — `docs/INDEX.md` claims a Diátaxis structure, but 50+ vision/roadmap/compliance files sit at the same level as `tutorials/`, `how-to/`, `reference/`, signaling a research project rather than a CLI tool to a first-time visitor. Move them into `docs/vision/` or `docs/advanced/`. Severity: low.

## Reduce

- **Shrink the public API surface of the library crate** — `src/lib.rs:41-76` — All ~20 modules (`adapters`, `engine`, `evidence*`, `ocel`, `nouns`, `ui`, `session`, `state`, `receipt_validation`, `oracle_keys`, `legacy_nouns`, `evidence_manifest`, …) are `pub mod` on a crate that is actually published to crates.io (`cargo-cicd = "26.6.30"`), yet `src/main.rs` — the crate's real and only documented consumer — builds its own separate `mod` tree rather than using the library API for most of them. Mark implementation modules `pub(crate)` or `#[doc(hidden)]`, keeping only `EngineState`, `CicdToml`, and the handful of state types used in the lib.rs doc examples as curated re-exports. Severity: high.
- **Make `cargo-cicd-lsp` an optional dependency gated by the `lsp` feature** — `crates/cargo-cicd-lsp/Cargo.toml:27-36`, root `Cargo.toml:96` — `tower-lsp`, `tokio` (full), and `jsonschema` (which drags in `regex` and schema-resolution machinery) are unconditional dependencies of a workspace member with no feature gating of its own, and the root crate depends on it as a plain non-optional dependency. Every `cargo build --workspace` compiles the full LSP + schema-validation stack for a verb most users never invoke. Sever: `dep:cargo-cicd-lsp` behind the existing `lsp` feature. Severity: medium.
- **Ship prebuilt binaries for the platform the project is actually developed on** — `.github/workflows/release.yml` — `build-release` runs only on `ubuntu-latest` and uploads a single `cargo-cicd-linux-amd64` artifact, despite the dev environment being Darwin. Neither the maintainer nor most contributors can install a working binary without a nightly source build, reintroducing the toolchain-pinning friction the tool exists to remove. Add a build matrix (linux, macOS x86_64/aarch64, optionally Windows). Severity: medium.
- **Lead the README with a plain-English sentence before the branding paragraph** — `README.md:8-12` — The opening line calls cargo-cicd "a sovereign admission controller and operational substrate... publication only proceeds on proven, admitted configurations (q_config = 1)" with no plain summary first; a newcomer cannot map this to an action in under ten minutes. Insert one concrete sentence ("checks your workspace health, runs only the tests your change affects, and gates publish behind a passing evidence trail") ahead of the framing language. Severity: medium.
- **Propagate serialization errors instead of `.unwrap()`-ing them on live command paths** — `src/nouns/doctor.rs:89,137,161,163`, `src/ocel.rs:1199-1201` — Four `serde_json::to_string_pretty(...).unwrap()` call sites in `doctor.rs` and two `.unwrap()` calls in `ocel.rs`'s `append_ocel_event` (the evidence-emission hot path) sit on live, non-test code. The structs serialized today can't actually fail, but this is inconsistent with the repo's own E3/E7 philosophy that adjudication failure is a diagnosable `Blocked`, not a panic. Propagate via `?` since the surrounding functions already return `Result`. Severity: low.
- **Stop double-exposing every engine state type at two import paths** — `src/engine/mod.rs:1-22` — The `pub mod workspace_state; pub use workspace_state::WorkspaceState;` pattern is repeated ten times, so every state type is reachable both as `engine::workspace_state::WorkspaceState` and `engine::WorkspaceState`, while types used directly in the lib.rs quick-start example (e.g. `GitPhaseState`) aren't re-exported to the crate root at all. Either privatize the submodules or re-export the flat names at crate root. Severity: low.
- **Return `Cow<'static, str>` instead of allocating a `String` per fixed ANSI color code** — `src/ui/style.rs:33-56,60-83` — All 16 fixed-color match arms in `fg_params`/`bg_params` call `.into()` on a `&str` literal, heap-allocating on every `Style::paint` call even though only `Fixed`/`Rgb` need `format!`. This runs once per styled span/cell across `table.rs`/`panel.rs`/`dashboard.rs`. Severity: low.
- **Verify `caps::unicode_enabled()` is memoized before every glyph call re-derives it** — `src/ui/symbols.rs:8-11,21-60` — `uni()` probes terminal capability on every one of ~20 glyph accessors, called repeatedly per dashboard render row; confirm it's cached via `OnceLock` (or add the cache) so the zero-dependency design doesn't cost a redundant env/TTY probe per glyph. Severity: low.
- **Reconcile the "zero-dependency" framing with `target_scanner.rs`'s real `walkdir` dependency** — `src/adapters/target_scanner.rs:2` — `src/ui/` is genuinely std-only, but `target_scanner.rs` pulls in `walkdir` for a task `std::fs::read_dir` handles in ~15 lines. Either drop the dependency or scope the "zero-dependency" claim explicitly to `src/ui/` in the docs. Severity: low.
- **Confirm `src/advanced/` modules are thin wrappers, not parallel reimplementations** — `src/advanced/histogram.rs`, `src/advanced/pattern.rs`, `src/advanced/fingerprint.rs` — The `advanced` feature already declares `hdrhistogram`, `aho-corasick`, and `blake3`; audit that these three files pass through to those crates rather than hand-rolling equivalent logic under a feature flag most users never enable. Severity: low.
- **Trim `Cargo.lock`'s ~385-crate default resolve** — `Cargo.lock` — Heavy relative to the value delivered by the always-on status/workspace/git/target verb path; re-run `cargo tree --duplicates` once the `cargo-cicd-lsp` and `advanced`-feature leakage above are gated, to find the next largest unnecessary subtree. Severity: low.
- **Pin an explicit nightly commit hash, not just a channel+date string** — `rust-toolchain.toml` — The workspace pin (`nightly-2026-06-22`) has no hash/checksum guarantee; no CI step verifies the resolved `rustc --version --verbose` commit hash matches an expected value, so a corrupted or silently-replaced nightly artifact for that date would be accepted. Severity: low.

## Raise

- **Give every `cargo cicd` noun a one-line `--help` description** — `src/main.rs` clap wiring, `ontology/public/cargo-cicd-capabilities.ttl` — Running `cargo cicd --help` shows blank descriptions for `verify`, `doctor`, `pipeline`, `trybuild`, `receipt`, `git`, `hooks`, `trace`, `workspace`, `publish`, `gate`, `ocel`, `target`, `test`, `evidence`, `status` — only `certification` and `sbom` have one-liners. The ontology TTL already has `dcterms:description` for every noun; the gap is in each noun's `about()` implementation, not the ontology. A newcomer's first command shows them nothing to act on. Severity: high.
- **Remove the crate-wide `#![allow(dead_code, unused_imports)]`** — `src/main.rs:1` — This inner attribute suppresses warnings for the entire binary crate, which is exactly how dead code like the unwired `anti-llm-cheat` noun and unused adapter twins goes unnoticed. Remove it, run `cargo build --all-features` / `--no-default-features` to see what lights up, and apply narrow, commented `#[allow(dead_code)]` only where justified. Severity: high.
- **Default the target-directory scan to the parallel path and stop swallowing scan errors** — `src/adapters/target_scanner.rs:14-26` — `total_size_bytes` walks `target/` single-threaded with one `metadata()` syscall per file, on the hot path of `EngineState::from_workspace()` called by nearly every `cargo cicd` invocation, against the exact directory CLAUDE.md itself flags as slow — while a faster `parallel_scan` already exists under the `advanced` feature but nothing calls it by default. Separately, `filter_map(|e| e.ok())` on both the walk and each `metadata()` call discards permission-denied and race-condition errors silently, so `total_size_bytes` can under-report with no signal, risking a false "pass" from the `target_pressure` policy. Make the parallel/cached path the default and return an error count alongside the byte total. Severity: high.
- **Parallelize the independent adapters inside `EngineState::from_workspace()`** — `src/engine/mod.rs:82-180` — Git status, toolchain detection, target-dir walk, changed-file git diff, and trybuild fixture scan all run strictly sequentially despite CLAUDE.md's own description of adapters as "stateless... never call each other," i.e. safe to parallelize. Several shell out to subprocesses. Use `std::thread::scope` (no new dependency) and merge results after joining. Severity: medium.
- **Surface which adapters failed instead of silently defaulting** — `src/engine/mod.rs:82-98` — `from_workspace()` uses `if let Ok(...)` fallbacks for git, toolchain, target, and changed-files detection with no recorded diagnostic; a workspace with broken git or a missing `Cargo.toml` produces an `EngineState` indistinguishable from a healthy sparse one except by manually inspecting fields for emptiness. Add a `pub diagnostics: Vec<AdapterDiagnostic>` field, surfaced by `workspace doctor` — this is exactly what the planned `standing.json` artifact needs to consume. Severity: medium.
- **Commit fully to the `EngineStateInner<State>` type-state, or drop it** — `src/engine/mod.rs:33-98` — `EngineStateInner<State>` derives `Default` generically, so `EngineStateInner::<Adjudicated>::default()` (i.e. `AdjudicatedEngineState::default()`) is directly constructible, bypassing `adjudicate()` entirely — the one place the phantom state does any work. Either make `Adjudicated` unconstructible except via `adjudicate()` and add at least one adjudicated-only method, or replace the phantom-typed split with a plain enum/bool field. Severity: medium.
- **Log instead of silently defaulting when `cicd.toml`'s carrier data can't be detected** — `src/cicd_toml.rs:41-60` — `detect_workspace_name`/`detect_toolchain` use `.ok()` at every step (file read, TOML parse, nested `get()`), so a genuinely malformed `Cargo.toml` or a permission error is silently absorbed into a generic `"workspace"` fallback — which then gets written back into `cicd.toml` as ground truth and propagated to evidence with zero operator-visible signal. Severity: medium.
- **Pin internal fleet crates consistently and exactly** — `Cargo.toml` — `workspace.dependencies` pins `cargo-cicd-core`/`cargo-cicd-lsp` with a loose `"26.6"` range (matches any future `26.x` release under Cargo's caret defaults) while `star-toml`/`chicago-tdd-tools` use exact `"26.6.30"` and `clap-noun-verb` uses a loose `"26.6.2"`. `cargo-cicd-core`/`cargo-cicd-lsp` resolve via their `path` entries in-workspace so the loose pin carries no real resolution risk there today, but `clap-noun-verb` is a true external dependency where the risk is live, and the inconsistency itself invites confusion under a calver scheme that abandons semver compatibility guarantees between bumps. Pin all first-party crates `=26.6.30`-style, consistently. Severity: medium.
- **Add `--locked` to CI's build/test/install invocations** — `.github/workflows/ci.yml`, `pr-checks.yml`, `release.yml` — `Cargo.lock` is tracked, but none of the project's own `cargo build`/`cargo test` calls (including the release-critical `cargo build --release`) pass `--locked`; only unrelated tool installs do. Combined with `deny.toml`'s `allow-git` sources, CI can silently resolve to different transitive versions than what was committed and tested. Severity: medium.
- **Add real signature verification to the oracle-key infrastructure, or rename it out of the trust boundary** — `src/oracle_keys.rs:1-160` — The module computes a non-cryptographic FNV-1a "fingerprint" (its own doc comment admits this isn't suitable for real verification) and embeds the raw `key_b64` value verbatim into every emitted XES trace — but nothing anywhere verifies an Ed25519 (or any) signature against it, and there is no sanity check that the value loaded from `CICD_ORACLE_KEY_B64` is actually a public key rather than an accidentally-pasted private one. The module's own doc comments ("so verifiers can independently validate signatures") overstate what the code does. Wire in real verification (e.g. `ed25519-dalek`) or rename/re-document this as fingerprint/rotation bookkeeping, and add a format/length sanity check before embedding the key verbatim. Severity: medium.
- **Canonicalize and clap-gate `target prune --apply`'s deletion path** — `src/legacy_nouns/target.rs:119-179` — `target_dir` is a hardcoded relative `"target"` string, `--apply` is detected via raw `std::env::args().any(|a| a == "--apply")` rather than the parsed clap `ArgMatches` (even though a proper `ArgAction::SetTrue` is registered and ignored), and `remove_dir_all` runs against `target/debug/{incremental,.fingerprint,deps}` with no canonicalization against a workspace root and no symlink check. Low blast radius for a local dev CLI, but below the standard expected for a destructive-delete path. Severity: medium.
- **Give the recurring `cargo-cicd-lsp` publish-bundling bug a CI regression test** — `crates/cargo-cicd-lsp/Cargo.toml` — Two of the three most recent commits fixed the exact same `include_str!`/publish path-depth bug back to back, indicating there is no `cargo package --dry-run` (or package-then-build-from-tarball) check in CI. Add one so include/exclude path mismatches are caught before merge. Severity: low.
- **Reserve `anyhow` for the CLI boundary; type library errors** — `src/ocel.rs:1207-1211`, `src/cicd_toml.rs:230` — Production code mixes `.map_err(|e| e.to_string())` (stringly-typed), `anyhow::anyhow!`, and bare `.unwrap()` within the same function, despite `thiserror` already being a declared (feature-gated) dependency. Define a `thiserror`-derived error enum per module boundary and reserve `anyhow` for `src/main.rs`/nouns. Severity: low.
- **Give the four "expected" oracle-unavailable panics a shared, greppable marker** — `src/evidence.rs:1058,1084,1111,1117` — Per invariant E3 these panics are intentional design, but four separate ad hoc `panic!` message strings make it hard to distinguish "expected-per-invariant panic" from a genuine crash in CI logs. Factor into one `fn oracle_unavailable_panic(context: &str) -> !` with a consistent `E3-VIOLATION:`-style prefix. Severity: low.
- **Require an explicit `rev` on any git dependency; drop the unused `chicago-tdd-tools` entry** — `deny.toml:29-33` — `[sources] allow-git` lists both `wasm4pm-compat` and `chicago-tdd-tools` by URL only; `cargo-deny` doesn't pin/verify a commit, and `chicago-tdd-tools` currently resolves as a registry dependency, so its entry is a dead trapdoor that would silently permit a future git-sourced switch to any commit, including rewritten history — the exact class of risk CLAUDE.md notes was already hit once with an unpinned wasm4pm-compat patch. Severity: low.
- **Give `status show`/`workspace doctor` messages a "why" and next-step command** — `src/engine/mod.rs:93`, `src/policies/*.rs` — Most policy suggestions already include an actionable fix command, but `cargo-cicd: warning: cicd.toml not admitted; using defaults` uses unexplained internal-law vocabulary ("admitted") with no next step. Replace with plain language and a pointer to a glossary entry; also move remediation text for a `git` FAIL up next to the summary line rather than only in the separate suggestions block. Severity: low.

## Create

- **Add a `just onboard` entrypoint and a `just standing` / `standing.json` recipe** — `justfile`, `README.md` Quick Start, `src/nouns/workspace.rs` — `UNIFICATION.md` states the goal directly: *"`just` plus `cargo cicd status` should be the complete surface a new developer ever needs to touch"* — and separately names a planned `standing.json` machine-readable repo-state artifact — but neither exists today. The `justfile` already has all 8 canonical fleet-contract recipes (check, build, test, clippy, fmt, doctor, verify-all, evidence) yet has no single onboarding recipe and no `workspace doctor` check that a repo's `justfile` actually exposes that canonical set. Add `just onboard` (toolchain install → `workspace doctor` → `status show`, narrated) as step 0 in the README, and a `standing` recipe that writes `standing.json` from `workspace doctor --format json`, plus a doctor sub-check that reports which canonical justfile recipes a repo is missing by name. Severity: medium.
- **Pin evidence file integrity across the emit-to-audit window** — `src/evidence.rs` (`audit_xes`/`audit_ocel`), `src/evidence_xes_v2.rs` — E1 assumes wpm's verdict is meaningful only if the bytes it audits are the bytes cargo-cicd wrote, but nothing hashes or signs the XES/OCEL file at emission time and re-verifies it immediately before the `wpm audit` subprocess call — a workspace under audit (or a CI step racing in between) can freely rewrite the file in that window with wpm none the wiser. Compute and store a content hash at emission time and refuse (not silently proceed) on mismatch immediately before shelling out to wpm. Severity: medium.
- **Add `cargo-binstall` metadata now that release binaries exist** — `Cargo.toml` — The release workflow already produces a prebuilt binary per tag, but `Cargo.toml` has no `[package.metadata.binstall]` section, so `cargo binstall cargo-cicd` falls back to a nightly source build — directly contradicting the project's own "without knowing cargo" onboarding vision. Add the `pkg-url` metadata (works for the single linux target today; extend as the release matrix grows) and document it as the primary install path. Severity: medium.
- **Publish an explicit semver/MSRV policy for the published library crate** — `Cargo.toml:32,34`, `src/lib.rs` doc comment — `version = "26.6.30"` is calver shared fleet-wide, not semver, and combined with the current all-`pub mod` surface, downstream fleet crates have no signal for what's a breaking change versus a routine version bump. State explicitly (and eventually enforce via `cargo public-api` diffing in CI) that only `EngineState`, `CicdToml`, and re-exported `cargo_cicd_core` types carry any compatibility guarantee. Severity: low.

## First wave

The five highest-leverage items to implement next, in dependency order:

1. **Remove the crate-wide `#![allow(dead_code, unused_imports)]` in `src/main.rs`** (Raise) — Size: **S**. Do this first — it's what's currently hiding the unwired `anti-llm-cheat` noun and the duplicate adapter pairs, so cleanup decisions below are made with real signal instead of guesswork.
2. **Delete or wire the dead code the above surfaces** — unused adapter-generation twins in `src/adapters/mod.rs`, and a decision on the `anti-llm-cheat` `LspNoun` (wire into `src/nouns/` or delete the feature entirely) (Eliminate) — Size: **M**. Directly depends on (1) for confident scoping.
3. **Add one-line `about=` descriptions for every noun** so `cargo cicd --help` stops showing 14 blank entries (Raise) — Size: **S**. Independent, trivial, and the single highest-visibility onboarding fix available — a newcomer's very first command currently gives them nothing.
4. **Default `TargetScannerAdapter` to the existing parallel/cached scan path and surface swallowed scan errors** (Raise) — Size: **M**. Independent of the above; the biggest concrete latency win since it runs on nearly every invocation via `EngineState::from_workspace()`, and it fixes a correctness gap (silent under-count feeding `target_pressure`) at the same time.
5. **Narrow the library's public API surface and publish an explicit semver policy** — mark internal modules `pub(crate)`/`#[doc(hidden)]`, keep a curated `EngineState`/`CicdToml` re-export set, document the compatibility boundary (Reduce + Create) — Size: **L**. Best done after (1)–(2) so the "what's actually internal wiring vs. load-bearing" call is made against a codebase that's already had its dead code named and removed.
