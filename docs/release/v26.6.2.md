# Release Notes — cargo-cicd v26.6.2

**Released:** 2026-06-14
**Previous release:** v26.6.1 (2026-06-01)

---

## What's New

### Evidence System — Process Conformance at Every Verb

v26.6.2 completes the evidence emission layer. Every verb now follows the same
pattern: a ProcessEvent is emitted on entry (`lifecycle_transition: start`) and
on completion (`lifecycle_transition: complete`) with a `verdict_claimed` of
`PASS`, `WARN`, or `FAIL`. Events are serialized to two companion files:

- `target/cargo-cicd/evidence/evt-<command>-<timestamp>.xes` — XML Event
  Stream, ready for `wpm audit`
- `target/cargo-cicd/evidence/evt-<command>-<timestamp>.jsonl` — machine-
  readable companion

`case_id` propagation groups related events into XES `<trace>` elements,
enabling end-to-end trace inspection across multi-verb pipelines.

Three new test suites enforce the evidence contract:

| Test file | Purpose |
|---|---|
| `tests/wasm4pm_evidence_gate.rs` | Happy-path: evidence emitted → wpm accepts |
| `tests/wasm4pm_evidence_mutation.rs` | Corrupt evidence must be refused by wpm |
| `tests/wasm4pm_refusal_cases.rs` | Edge cases: oracle unavailable, malformed XES |

### git Noun — Full Phase Tracking

Six verbs are now available under the `git` noun:

| Verb | Description |
|---|---|
| `git status` | Branch, dirty files, staged, untracked, ahead/behind counts |
| `git close` | Enforce phase closure — refuses to close with a dirty tree |
| `git diff` | Show staged and unstaged changes |
| `git stage` | Stage modified tracked files (`git add -u`) |
| `git commit` | Create a commit with an auto-generated message |
| `git fetch` | Fetch from remote origin |

`git close` is the primary release gate: it checks that the working tree is
clean, all tests have passed, and the phase is closeable before advancing.

### workspace Noun — Diagnostics and Sync

| Verb | Description |
|---|---|
| `workspace doctor` | Autonomic policy checks + full workspace health snapshot |
| `workspace validate` | Validate Cargo.toml structure and member declarations |
| `workspace sync` | Invoke `ggen` to regenerate outputs if `ggen.toml` is present |
| `workspace list` | List all workspace member crates with paths |

`workspace doctor` is now the primary entry point for the autonomic layer — it
runs all 7 policies and emits a structured recommendation set.

### test Noun — Changed-File Selectivity

`test changed` selects only the test files touched by the current git diff
against `origin/main`. This avoids running the full suite on every commit while
keeping the changed-file detection precise. The conservative mode invariant
(`INVARIANT_NO_FULL_TRYBUILD_BY_DEFAULT`) remains enforced.

### LSP Integration (crates/cargo-cicd-lsp)

The language server now registers 13 analyzers covering the full workspace
lifecycle:

- workspace-structure
- pipeline-check
- remote-tracking
- changed-tests
- git-phase
- target-hygiene
- public-boundary
- publish
- ggen-customization
- rendered-surface
- close-readiness
- (and 2 additional internal analyzers)

Findings follow a 5-state lifecycle:

```
Raised → PendingRepair → Routed → ResidualPreserved → Cleared
```

The `DiagnosticStore` persists findings across LSP requests, enabling
incremental updates without rescanning the full workspace on every edit.

10 new `CicdCode` variants were added to `crates/cargo-cicd-core` to cover
the expanded analyzer surface.

### Core Diagnostics (crates/cargo-cicd-core)

New introspection methods on `CicdCode`:

```rust
CicdCode::category()           // group codes by category string
CicdCode::codes_by_category()  // list codes per category
CicdCode::all_variants()       // enumerate every known code
```

`Severity::is_blocking()` returns `true` for any severity that must halt a
release. This is the authoritative check used by `git close` and the publish
gate.

`DiagnosticLifecycle` is a new enum with 5 variants matching the LSP finding
lifecycle above.

### Autonomic Policies — 7 Policies, Real EngineState

All 7 policies now receive a fully-populated `EngineState` (previously
`Default::default()` was passed, making most policies useless):

| Policy | Trigger | Recommendation |
|---|---|---|
| `git_phase_dirty` | Dirty or staged files present | Commit or stash before closing |
| `target_pressure` | Target directory exceeds size threshold | Run `cargo cicd target prune` |
| `toolchain_mismatch` | Active rustc != lockfile expectation | Update toolchain or lock |
| `trybuild_changed` | Trybuild fixtures changed | Run `cargo cicd trybuild changed` |
| `branch_behind` | Local branch behind origin/main | Pull or rebase |
| `evidence_stale` | Last evidence file older than threshold | Re-run evidence gate |
| `publish_not_adjudicated` | Publish ran without wpm verdict | Require wpm oracle for releases |

Policy inputs are now typed: `WorkspaceInfo`, `GitState`, and `EvidenceState`
are passed as distinct arguments rather than a single opaque struct. This
removes the ambiguity that caused the `Default::default()` regression.

### EngineState — All 11 Dimensions Populated

`EngineState::from_workspace()` now initializes all 11 state dimensions from
real adapters. Previously several dimensions fell back to `Default::default()`
when their adapter encountered a non-fatal error. Silent partial population is
now logged (not silenced) so callers can detect degraded state.

`ManifestParser` was added as a lightweight alternative to invoking
`cargo metadata` — it parses Cargo.toml directly via the `toml` crate, keeping
the adapter in the "fast" tier.

## Breaking Changes

None. v26.6.2 is fully backward-compatible with v26.6.1.

## Migration Guide

No migration steps are required when upgrading from v26.6.1.

If you have scripts that inspect `target/cargo-cicd/evidence/`, note that the
directory layout is unchanged; only new files are added.

## Known Issues

### wpm Oracle Required for Full Evidence Gate

The `wasm4pm_evidence_gate`, `wasm4pm_evidence_mutation`, and
`wasm4pm_refusal_cases` test suites call the `wpm` binary at runtime. If `wpm`
is not on your `PATH`, all three suites will produce `Blocked` verdicts rather
than `Accept`/`Refuse`.

For local development without `wpm`, declare `ExpectedWpmVerdict::Blocked` in
your test assertions — this is a first-class expectation, not an error.

For release gating, `wpm` must be available:

```sh
wpm --version          # confirm binary is present
wpm audit <file.xes>   # should print Accept, Refuse, or Blocked
```

## How to Upgrade from v26.6.1

```sh
# If installed via cargo install:
cargo install cargo-cicd --version 26.6.2

# Or build from source:
git fetch origin
git checkout v26.6.2
cargo make build

# Verify:
cargo cicd --version    # should print 26.6.2
cargo make test         # all 277 tests should pass
```

After upgrading, run `cargo cicd workspace doctor` once to populate the updated
evidence state and confirm all autonomic policies pass.
